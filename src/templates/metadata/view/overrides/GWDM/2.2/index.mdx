## Level 1 - the default

Each section's fields are label/value rows, nested objects walked down to
their leaves. Lists render as chips, including this schema's legacy
`;,;`-delimited strings - `keywords` arrives as one long string and still
comes out as one chip per keyword.

<MetadataView path="summary" />

## Level 2 - scoping with `path`

`path` resolves the data and the schema together, unwrapping `$ref`s at each
hop. That is the only way to reach a nested node: every property in these
schemas is an `allOf`/`anyOf` wrapper, so `props.schema.properties.summary`
has no `.properties` of its own to index into.

<MetadataView path="summary.publisher" />

The explicit form is still there for data you have computed yourself, where
there is no path to point at:

<MetadataView
  data={{ ...props.data.summary, abstract: undefined }}
  schema={props.schema.properties.summary}
/>

## Level 3 - overriding a renderer

Here the *section wrapper* is replaced rather than the values, by overriding
`Section`. The field rendering underneath is untouched.

{/* The components map resolves JSX element NAMES, not bare identifiers, so an
    injected component is referenced as <CardSection /> rather than passed
    directly as `Section: CardSection`. */}

<MetadataView path="coverage" components={{ Section: p => <CardSection {...p} /> }} />
